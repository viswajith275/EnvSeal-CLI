01 — The problem

If you've built anything with more than one contributor, you've probably lived one of these: a teammate adds a key to their local .env and forgets to send it. Someone pastes a database URL into a Discord DM. You check out a branch and accidentally run it against production. A sleepy git add . scoops up a raw key and it sits in Git history forever.

And the one nobody warns you about: half your secrets aren't strings. The TLS certificate in certs/. The service-account JSON someone sent you at 11pm. The kubeconfig with production cluster access. They don't fit in .env, so they end up on a shared drive, in a wiki attachment, or in a "temporary" commit that quietly became permanent. EnvSeal seals the files too — and injects them at runtime as a private temp path.

None of these are exotic. They're what happens when secrets live outside version control and the code that needs them doesn't.

The fix isn't a better .env file. It's putting your vault somewhere Git already knows how to move. EnvSeal makes your secrets a file in your repo — encrypted for the people who need them, switched by branch, and reviewed in pull requests like anything else you commit.

02 — The workflow

Two columns. That's the whole pitch.

You set up the vault, add your teammate as a recipient, commit, and push. They pull, run their app, and it works. Same keys, same certificates, correct branch, zero DMs.

03 — What's inside

Ten decisions that shape everything else.

01
Git-native by design
The vault is a file in your repo. Pull requests, git blame, and history apply to secrets the same way they apply to code.
02
Branch-aware
envseal run reads git rev-parse --abbrev-ref HEAD and applies the tag with the same name, if one exists. No manual swapping.
03
Per-recipient access
The vault is sealed to individual public keys. Adding a teammate is a Git commit, not a shared-key redistribution. Removing one needs a follow-up rotate.
04
Ephemeral runtime
Text secrets are injected into the child process environment and disappear on exit. Sealed files decrypt to a private temp path that is overwritten and deleted when the process ends. No plaintext file is left behind.
05
Pre-commit shield
A hook blocks staged .env files and their variants before they reach Git history. Examples like .env.example and the encrypted vault pass through.
06
Merge driver included
Two people editing secrets on different branches usually resolve silently. Same key, different values? You pick ours or theirs.
07
Interactive editor
envseal edit opens the vault in your $EDITOR, writes only the diff back, and zeroes the temporary plaintext on exit. Bulk edits without dozens of set calls.
08
Global + local vaults
Keep personal tokens in a system-wide vault, then pull them into a project on demand — --override KEY for one key, --with-global for everything.
09
Multiple profiles
Need more than branch tags? Target per-environment vaults with -e staging or -e prod — no extra repos, no extra setup.
10
Files, not just strings
TLS certificates, service-account JSON, .p12 keystores, SSH keys, and kubeconfigs are sealed in the same vault. envseal run decrypts each one to a private temp file, points an env var at it, and overwrites and deletes it when the process exits. envseal get KEY -o PATH writes it back out — new files get 0600 (or 0700 if executable) — when a tool insists on a fixed path. No shared drive. No wiki attachment. No stale copy with production access.

05 — The deal

Read this before you trust any encryption tool.

Most encryption tools hide their limits in the fine print. We put them on the landing page. If any of them is a dealbreaker, EnvSeal is not for you — and that's fine.

01
Removing someone is not the same as rotating the key.
+
envseal recipient rm re-wraps the vault key for everyone else, but it keeps the same data key. Anyone who unlocked the vault before still holds that key and could decrypt future commits. Run envseal rotate immediately after removing someone — that generates a new data key. And Git history is permanent: anyone who cloned earlier can still decrypt old commits with the old key. If someone leaves under bad terms, rotate the actual credentials too. Removing their access is taking away the house key after they've already made a copy.
02
envseal rotate protects the future, not the past.
+
Rotation re-encrypts the current state of the vault, which is exactly what you want after a compromise. But it does not retroactively re-encrypt old Git commits. Those snapshots stay encrypted under the old key. The only thing that actually neutralizes a leaked secret is changing the secret itself. So: rotate the vault and go rotate the API keys or database passwords at the source.
03
Token expiry is enforced by the CLI, not by cryptography.
+
The --exp flag is a runtime check performed by EnvSeal itself. Because everything is offline, there's no server refusing an expired token — a sufficiently determined attacker with the raw payload could bypass the clock. Treat expiry as a guardrail, not a guarantee. If a CI runner is ever compromised, rotate the vault and the underlying secrets immediately.
04
If you're your only recipient, you're also your only point of failure.
+
EnvSeal has no "forgot password" button, and it never will — that's the entire point of zero-trust design. If your laptop dies, gets stolen, or falls in a lake, there's no cloud backup, no support ticket, and no admin override. Treat your Age/SSH identity like a seed phrase: back it up outside the repo, and consider adding a second recipient purely as a recovery path.
Where EnvSeal genuinely wins
  • Git-native by design. The vault is a file in your repo, not a parallel system you have to remember to sync.
  • Free and offline. No accounts, no cloud, no telemetry. Works on a plane or behind a corporate firewall.
  • Branch-aware. Run envseal run on staging and it applies the staging tag automatically — no flag, no copy-paste.
  • Per-recipient access. Adding a teammate is a Git commit, not a shared-key redistribution. Removing one needs a follow-up rotate.
  • Files, not just strings. Certificates, service-account JSON, and kubeconfigs are sealed and injected as private temp paths — not shared as attachments.
  • Global + local vault mixing. Personal tokens stay in a system vault; projects only pull what they need.
Where it's honestly not the best fit
  • No web dashboard, no audit log. If you need to see who accessed what and when, use a cloud tool.
  • No non-technical UI. Everyone on the team touches a terminal. If that's a dealbreaker, look at Doppler or Infisical.
  • You can lock yourself out permanently. Zero-trust means zero recovery. Back up your key.
  • Kubernetes / cloud-KMS shops. SOPS fits your existing pipeline better than bolting EnvSeal on.
06 — Reference

The whole CLI, at a glance.

The commands and flags you'll actually use. If you've used Git, this will feel familiar — every command is a single verb, and most have a natural Git analogue you already know.

Core

envseal init [--local] [--git] [-r RECIPIENT]
Initialize a project-local vault or a global vault. -r adds an initial recipient.
envseal git-setup [--init]
Register the merge driver and pre-commit shield in the current repo.
envseal set [-g GROUP] [-t TAG] [--file PATH] [--env-var VAR] KEY
Store a secret without echoing it, or seal an entire file with --file.
envseal get [-g GROUP] [-t TAG] [--token TOK] [-o PATH] KEY
Print one decrypted value, or write a sealed file back to disk with -o.
envseal run [-g GROUP] [-t TAG] [--token TOK] [--clear] [--override K1,K2 | --with-global] -- CMD (alias: exec)
Run a command with secrets injected into the child process. Mix in global-vault keys with --override or --with-global.
envseal load [-g GROUP] [-t TAG] [--token TOK] [--override K1,K2 | --with-global] [KEYS...]
Print shell export statements for eval. Prefer run.
envseal list [-g GROUP] [-t TAG] (alias: ls)
List key names without revealing values.
envseal edit [-g GROUP] [-t TAG]
Edit key/value pairs in your default editor. Temp file is zeroed on exit.
envseal remove [-g GROUP] [-t TAG] [--force] [KEY] (alias: rm)
Delete a key, tag, or group. --force skips confirmation.
envseal link GROUP
Bind a global vault group to the current working directory.
envseal clear
Wipe cached master keys from the OS keyring session.

Sealed files

envseal set KEY --file PATH [--env-var VAR]
Seal any file up to 10 MB. run injects $VAR as a private temp path; the variable defaults to KEY.
envseal get KEY -o PATH
Write a sealed file back to disk. New files get 0600 (or 0700 if executable); overwriting keeps the existing file's mode. Pipe stdout for raw bytes.

Global vault override

--override KEY1,KEY2
Pull only the named keys from the global vault. Conflicts with --with-global.
--with-global
Overlay all keys from the global vault. Global wins on collision. Conflicts with --override.
--global-group GROUP
Which group inside the global vault to use. Defaults to the directory's linked group.
--global-tag TAG
Optional tag inside that global group. Defaults to base.

Access & CI

envseal recipient id
Print your local public identity key. Share it once with the vault owner.
envseal recipient add <@user | KEY | FILE>
@user fetches GitHub SSH keys. Falls back to a manual age key if they have none.
envseal recipient ls
List all authorized recipient keys.
envseal recipient rm <NAME | INDEX | KEY>
Remove a recipient and re-wrap the vault key. Run rotate to change the data key.
envseal token [-t TAG] [-o PATH] [--exp S] [KEYS...]
Mint a scoped, offline CI token. Limit by tag, by key, and by expiry.
envseal rotate
Rotate the encryption key. Every existing token becomes unreadable.
envseal import [-t TAG] PATH
Import variables from an existing .env file. Original left in place.
envseal export [-t TAG] [-o PATH] [--override K1,K2 | --with-global] [KEYS...]
Decrypt to a .env file with strict 0600 permissions.

Global flags

-e, --env PROFILE
Target a specific profile file. -e staging loads .staging.envseal.
-G, --global
Target the system-wide vault. Comes before the subcommand: envseal --global init.
--no-env
Disable reading fallback identity keys from ENVSEAL_IDENTITY and ENVSEAL_IDENTITY_FILE.

★ View on GitHub
Q
Does it work with Docker / Docker Compose?
+
Yes. Build your image normally, then at runtime do envseal run -- docker compose up, or inject only the keys you need into the container environment.
Q
Does it work with monorepos?
+
Yes. Keep one .envseal at the root, or put a separate .envseal in each package — EnvSeal uses the nearest one. Use the -e profile mechanism when you want multiple vaults side by side.
Q
What's the difference between --override and --with-global?
+
--override KEY1,KEY2 pulls only the named keys from the global vault. --with-global overlays all keys from the global vault, with global values winning on collision. They are mutually exclusive.
Q
Can I store a TLS certificate, SSH key, or kubeconfig?
+
Yes — that's what file secrets are for: envseal set TLS_CERT --file ./certs/server.pem --env-var TLS_CERT_PATH. During envseal run, the file is decrypted to a private temp path, the env var points at it, and it's overwritten and deleted when the process exits. Need a fixed path? Use envseal get TLS_CERT -o ./server.pem. export and load only handle text variables: export warns for every skipped file secret, load warns when you explicitly name one.
Q
What happens when two people edit secrets at the same time?
+
The Git merge driver resolves most edits silently. If two contributors change the same key to different values, it stops. Pick a side by re-running the merge with git -c envseal.merge.strategy=ours merge … or theirs.
Q
What if my teammate doesn't have SSH keys on GitHub?
+
envseal recipient add @handle will fail. Ask them to run envseal recipient id, which creates or reuses their local identity. They send you the output, and you add it with envseal recipient add "age1...". Same result, one extra paste.
Q
I forgot my private key and I'm the only recipient.
+
This is not a bug EnvSeal can fix — it's a backup problem. If you still have the identity file somewhere (another machine, a password manager, a printed seed), restore it and you're fine. If you don't, the vault is a locked box with no key.
